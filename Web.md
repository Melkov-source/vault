**Клиентская часть:**
1. Cocos Creator
   Игровой движок, заточенный под разработку в веб среде и с использованием веб стека.
   Документация: https://docs.cocos.com/creator/3.8/manual/en/
   
   Его удобнее всего использовать в контексте веба, потому что работа происходит непосредственно в нужно среде разработки. Удобно дебажить через DevTools.
   
   Однако движок не самый устойчивый и не редко возникают какие-то странные проблемы (по началу многое может быть странным и не очевидным). Например редактор не очень хорошо синхронизирует файлы и изменения в них, особенно если речь идет о системе префабов или мета информации файлов.
   
   Так же можно отметить, что сборка билдов просиходит весьма быстрой.
   
   Это основные языки на которых происходит разработка
	- Java Script / Type Script
	- CSS / Tailwind / HTML

1. Unity
   В данный момент это предпочтительный движок для разработки веб игр, однако он достаточно тяжелый в качестве решения, так как само ядро движка написано на C++, а скриптинг основан на C#. Все это дело компилируется сначала в il2cpp, после чего в WebAssembly для работы в среде JavaScript.
   
   Основная проблема использования заключается в том, каким образом скриптовая логика игры взаимодействует с веб окружением и наоборот. Для этого нам приходится писать некоторый мост между этими средами и обмениваться пакетами в виде json.
   
   Исходя из этого, дебаг в веб окружении может быть нормальным только со стороны веб окружения, а что касается кода написанного на C# - здесь дебажить можно только логгером. Поэтому если нужно что-то хорошо отдебажить со стороны C# - делается это в редакторе, где отсутсвует веб окружение. А после сборки билда мы теряем нативное окружение и дебажить может только веб окружение.
   
   Еще есть проблема с долгими сборками, которые могут быть от 30 минут до часу (если не больше, но зависит от самого проекта и пайплайна сборки). Поправил одну строчку в C#? Ну что, жди 30 минут, пока соберётся билд. Поэтому мы стараемся все проверять на стороне редактора и писать отдельные реализации с фейковым поведением веба. 
   
   Основные языка с которыми работаем:
	- C#
	- Java Script / Type Script
	- CSS / Tailwind / HTML
	- Rollup / Terser
	  Мы на стороне веб окружения используем систему сборки основанную на Rollup, потому что это показалось весьма удобным, где можно описывать пайплан. Ну и добавляем для продакшена Terser, чтобы минифицировть и обфусцировть код

**Серверная часть:**
1. Nest.js / Express
   Бекед изначально мы писали на Express, где все нужно было делать ручками, прописывая маршруты и обрабатывая миделвары. В общем приходилось изобретать велосипеды.
   
   После решили попробовать фреймворк Nest.js, который предоставляет весьма удобную модульную систему и кучу еще чего, что полезно использовать при написании бекенда. Поэтому если тебе захотелось использовть систему кэширования на основе Redis? Пожалуйста, здесь есть несколько уже готовых решений, достаточно просто подключить модуль.
   
1. Docker
   Чтобы серверное приложение работало стабильно, мы используем докер для создания контейнеров под конкретный образ приложения. Это удобно и практично.
	- Portainer
	  Просто удобная админ панель для управления докером
	- Dockerfile
	  Здесь бывает описываем для докер образов, как должно запускаться и работать наше приложение в контейнере
	- Docker Compose
	  Это используем в основе, потому что в нем можно понятно описывать сервисы и настраивать между ними связи.
	- Dozzle
	  Логи из контейнера можно просматривать различными способами, начиная от терминала и Portainer, но все это не очень удобно, да и не сохраняются дампы логов. А Dozzle - это мощная система работы с логами для докера.
	- Caddy
	  Используем для настройки http сервера. В нем можно удобно описывать конфигурации сервера на простом DSL. + под капотом он дает возможность использовать SSL сертификаты, чтобы сделать https автоматически. И небольшая фича в виде установки пароля на конкретные маршруты.
