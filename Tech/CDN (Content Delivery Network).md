**CDN** — это сеть геораспределённых серверов, обеспечивающая **быструю доставку контента** пользователю. Контент (изображения, скрипты, страницы и пр.) отдается с ближайшего к пользователю узла, что снижает **задержки**, уменьшает нагрузку на основной сервер и повышает **отказоустойчивость**.

Основные принципы работы:
- **Кэширование** ресурсов на edge-серверах;
- **Маршрутизация** запросов к ближайшему географически узлу;
- **Edge computing** — выполнение логики прямо на CDN-узле.

1. Настроить кеширование
   -  CDN Invalidation: ручное удаление кеша при обновлении файлов.
   - `ETag`: сервер возвращает уникальный хеш ресурса. Браузер при повторном запросе шлёт `If-None-Match`.
   - `Cache-Control`: задаёт правила хранения (`no-cache`, `max-age` (Time To Live), `public`). Механизм, при котором CDN и браузер долго хранят файл в кэше, чтобы не загружать его заново.

2. Работа с MIME-типами
   Формальный способ сказать браузеру, какого типа файл он получает (например, JS, CSS, JSON). CDN или сервер добавляет заголовок `Content-Type`. 
   
3. Edge computing (можно изменять запросы/ответы на границе)
   Выполнение кода ближе к пользователю, на CDN-узлах (границе), а не на централизованном сервере.
   CDN запускает функции (JS, WASM и т.п.) при каждом запросе.

# Cloudflare
1. Настройка домена и DNS
	1. Подключение домена к Cloudflare
	   Нужно указать Cloudflare как DNS-провайдера у регистратора, заменив NS-записи. Это необходимо сделать, чтобы Cloudflare мог работать полноценно с DNS
	   
	2. DNS-записи
	   Нужно создать `A` или `CNAME` записи, указывающие на origin-сервер.
	   В нашем случае мы использовали обычный статичные сервер, настроенный через Caddy, в котором предварительно прописаны все заголовки для разных MIME типов файлов - для компрессии и для кеширования (TTL Browser)
	   
2. Конфигурация кэширования
	1. Cache Rules
	   Необходимо создать правила, которые будут говорить всем точкам присутствия какие ресурсы должны кэшироваться и каким образом. Там можно сделать условия реагирования правил по маршрутам, домену и т.д. Указать определение заголовков кеширования как на Browser стороне, так и на Edge. 
	   
	   На проекте мы сделали так, чтобы кеширование брало все настройки с origin-сервера. А для edge серверов настроено через правило.
	   
	   Так же мы кешируем все статичные данные, кроме главной страницы /index.html, дабы она бралась с origin-сервера и была всегда актуальной.
