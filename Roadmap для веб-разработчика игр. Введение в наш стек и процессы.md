Этот документ — отправная точка для погружения в наши проекты. Здесь описан наш технологический стек, подводные камни и лучшие практики. Используй это как руководство и шпаргалку.

#### **С чего начать изучение?**

1. **Поставь всё!** Установи Unity, Cocos Creator, Docker Desktop, Node.js.
2. **Серверная часть:** Самый быстрый способ — пройти туториал по NestJS. Создай простой REST API с одним модулем, подключи его к локальной БД через Prisma и заверни всё в Docker-контейнер.
3. **Клиентская часть:**
    - **Unity:** Собери простейший WebGL-проект (куб, который вращается) и попробуй вызвать из C# функцию `console.log` в браузере. Ну и наоборот, сделай в вебе кнопку, нажатие которой перекрасит этот куб в рандомный цвет.
    - **Cocos Creator:** Создай новую сцену с спрайтом и напиши скрипт на TypeScript, который будет двигать его по клику. Посмотри, как это работает в браузере и открой DevTools.

#### **Клиентская часть (Игровые движки)**

Наши игры работают в вебе, поэтому мы используем движки, которые компилируются в WebAssembly (WASM) и WebGL. Выбор движка зависит от проекта.

**1. Cocos Creator**  
* **Описание:** Современный игровой движок, _заточенный_ именно под веб. Полностью использует веб-стек (TypeScript, WebGL), что обеспечивает глубокую интеграцию с браузером.  
* **Преимущества:**  
* **Быстрые итерации:** Холодный старт редактора и сборка билдов происходят очень быстро.  
* **Прямая интеграция с Вебом:** Дебаг через Chrome DevTools — это одно из главных преимуществ. Ты видишь DOM, Network, Sources, Console так же, как при обычной веб-разработке.  
* **Язык:** TypeScript из коробки.  
* **Стабильность редактора:** Редактор может быть неустойчивым. Часто возникают проблемы с синхронизацией файлов (особенно мета-файлов и префабов). **Лучшая практика:** Закрывать редактор перед операциями с git (мерж, переключение веток) и периодически чистить кэш (`Project -> Refresh Preview` и `Project -> Reload`).  
* **Меньше материалов:** По сравнению с Unity, сообщество и количество обучающих материалов меньше.  
* **Документация:** [https://docs.cocos.com/creator/3.8/manual/en/](https://docs.cocos.com/creator/3.8/manual/en/)  
* **Форум:** [https://forum.cocos.org/](https://forum.cocos.org/) — активно отвечают сами разработчики движка

**2. Unity (WebGL)**  
* **Описание:** Наш основной движок для более сложных проектов. Мощный, с огромным сообществом, но его интеграция в веб требует особого подхода.  
* **Архитектура:** Ядро движка (C++) и код игры (C#) компилируются в **WebAssembly**. Для взаимодействия с браузером (JavaScript) мы используем систему взаимных вызовов.  
* **Взаимодействие C# <> JS:** Мы написали специальный **"мост"** для обмена данными (обычно в формате JSON). Это добавляет слои абстракции.  
* **Дебаггинг:** Это самая большая сложность.  
* **Код на C#** можно полноценно дебажить только в редакторе Unity. В веб-сборке остаются только логи.  
* **Код на JS** дебажится в DevTools.  
* **Решение:** Мы пишем симуляторы веб-окружения для редактора Unity, чтобы тестировать логику на C# без постоянной сборки под WebGL.  
* **Время сборки:** Долгое! Может занимать от 30 минут до часа+.  
* **Стратегия:** Максимально тестируем всё в редакторе.
* **Ключевые технологии:**  
* **C#** — основная логика игры.  
* **JavaScript / TypeScript** — веб-часть, коммуникация с бекендом, API.  
* **Rollup + Terser** — используем для сборки и минификации/обфускации нашей веб-части. Это дает нам контроль над процессом.  
* **CSS / Tailwind CSS** — для стилизации UI элементов на веб-странице, обертывающей игру.  
* **Документация по WebGL:** [https://docs.unity3d.com/Manual/webgl-building.html](https://docs.unity3d.com/Manual/webgl-building.html)  
* **Взаимодействие с JS:** [https://docs.unity3d.com/Manual/webgl-interactingwithbrowserscripting.html](https://docs.unity3d.com/Manual/webgl-interactingwithbrowserscripting.html)

#### **Серверная часть (Backend)**

**1. Фреймворк: NestJS**  
* **История:** Начинали с Express, но для поддержки растущей кодовой базы перешли на **NestJS**.  
* **Преимущества:**  
* **Модульность и структура:** Предоставляет из коробки продуманную архитектуру (модули, контроллеры, сервисы), что упрощает разработку и поддержку.  
* **TypeScript:** Полная поддержка.  
* **Экосистема:** Множество готовых модулей для подключения (Redis, GraphQL, TypeORM, Prisma и т.д.). Нужен Redis? Просто установи `@nestjs-modules/ioredis`.  
* **Ресурсы:**  
* **Официальный сайт:** [https://nestjs.com/](https://nestjs.com/)  
* **Документация:** [https://docs.nestjs.com/](https://docs.nestjs.com/)

**2. Базы данных и ORM**  
* **MySQL:** Основная реляционная база данных для хранения structured-данных (данные пользователей, прогресс, инвентарь).  
* **Prisma ORM:** Современный TypeScript-friendly ORM. Нам нравится за:  
* **Безопасность типов:** Схема БД генерирует TypeScript-типы.  
* **Интуитивный API:** Удобные и читаемые запросы.  
* **Миграции:** Система миграций работает из коробки.  
* **Redis:** Используется как кэш-сервер быстрого реагирования (для сессий, временных данных, очередей) и для pub/sub.

**3. Деплой и Инфраструктура (Docker)**  
Мы используем Docker для создания предсказуемых и изолированных сред выполнения.  
* **Dockerfile:** Инструкция для сборки образа нашего приложения.  
* **Docker Compose:** Инструмент для определения и запушения многоконтейнерных приложений. Удобно описывать сервисы (app, db, redis, nginx) и их связи в одном файле `docker-compose.yml`.  
* **Инструменты для управления:**  
* **Portainer:** Веб-интерфейс для управления докером (контейнеры, образы, тома). Удобно для визуального контроля.  
* **Dozzle:** Легковесный инструмент для просмотра логов контейнеров в реальном времени в браузере. Не хранит логи, но идеален для оперативного дебаггинга.  
* **Веб-сервер: Caddy**  
* **Почему Caddy?** Простота настройки. Конфиги пишутся на понятном языке. Он автоматически управляет SSL-сертификатами (HTTPS) через Let's Encrypt. Также есть удобные фичи вроде базовой авторизации для защиты staging-окружений.  
* **Ресурсы:**  
* **Docker Docs:** [https://docs.docker.com/](https://docs.docker.com/)  
* **Docker Compose:** [https://docs.docker.com/compose/](https://docs.docker.com/compose/)  
* **Caddy:** [https://caddyserver.com/](https://caddyserver.com/)
